# 叙事与实验契约

## 读者路线

首屏用一句具体问题建立动机，一小段文字说明读者将学会什么，给出「开始探索」和「试用完整项目」两个入口。用一张很小的关系图展示整体想法；首屏不堆组件库截图或营销指标。

章节区是正文。左侧目录提供阅读位置，右侧用提问式标题和两三句原理导入，接独立机制图、当前模块讲解和本章实验。实验后用一句话收束观察结论，并给出必要的适用边界。最后再给完整 Demo 和代码/架构文档入口。

这是技术科普的叙事：问题 → 因果 → 亲手改变 → 可见证据。准确解释先于广告措辞；不要让产品功能清单替代机制。

## 可选的七种章节功能

以下是原页面成功的叙事顺序。选择目标项目真正存在的机制，按需要合并、重排或删除。React、Worker、模型、DSL、SSE、沙箱都不是模板必备技术。

| 章节功能   | 问题形式                     | 适合的拓扑                  | 有意义的实验                                           |
| ---------- | ---------------------------- | --------------------------- | ------------------------------------------------------ |
| 总览       | 输入怎样成为结果？           | 流水线，加一条必要依赖      | 追踪一个输入的中间产物和最终结果                       |
| 状态与反馈 | 操作后什么改变、由谁计算？   | 交互闭环                    | 改变选择，观察局部状态/结果，证明无关状态保持          |
| 渐进与恢复 | 尚未完成或出错时如何继续？   | 阶段分支、恢复/回退路径     | 实际分批处理、失败恢复或取消续作；不是只有播放进度动画 |
| 数据与规则 | 换一份数据，规则是否复用？   | 两种独立输入汇合            | 保持规则/选择，换数据快照，观察重算结果                |
| 执行边界   | 哪些输入允许，哪些会被拒绝？ | 控制边界、校验门或隔离区    | 合法/非法输入对照，观察真实诊断或边界行为              |
| 显式提交   | 当前状态如何交给下一阶段？   | 选择 → 提交 → 接收者 → 结果 | 捕获确实提交的参数与结果，区分选择和提交               |
| 证据范围   | 本次实验到底证明了什么？     | 实现、运行、输入来源与限制  | 从实际执行记录确认覆盖，不用静态打勾冒充验证           |

例如非 AI 的搜索系统可用「建索引、查询匹配、数据重建」三章；后台队列可用「入队、调度、重试、幂等、监控」五章。没有渐进生成机制就不制造“流式生成”章节；没有两种实际路线就不虚构路线切换。

## 一章的完成条件

示例契约：

- 问题：网络快照变化时，为什么端口选择还能保留？
- 图：数据源和稳定程序分别进入运行时，再到端口显示；不存在必须绕经模型的边。
- 操作：选中端口 8，从正常快照切到故障快照。
- 保持：程序、端口选择。
- 变化：端口 7 中断、端口 8 的 CRC 和汇总速率变化。
- 证据：实际 appData、状态与本次 UI 操作；重置可重复观察。
- 范围：使用模拟遥测验证数据绑定，不声称连接了真实设备。

对任何其他业务都使用同样的契约形式，但换成其真实对象与机制。图解、讲解代码、控件标签、实验说明使用一致名称。一个节点写的是“宿主提交”，实验若只预览 payload，就明确说预览，并指向完整 Demo 中实际提交的路径。

## 图解语义

每条箭头回答“谁向谁传什么”。区分数据/程序与事件/动作，并提供图例。分叉必须有真实条件或不同产物，合流要说明两种输入各自来源。边界框说明责任或执行范围，不能仅靠 Worker / iframe 名字就宣称安全隔离。

图中的虚线流动表示路径方向和教学引导；默认不是运行时事件流。若连接真实日志，明确标注并让节点/边由实际事件驱动。自动导览的 STEP 次序只是阅读顺序，不自动等于因果次序、拓扑顺序或时序。

一章可有多个节点，章节编号与节点编号各自独立。切章同时切换图、模块讲解、实验和说明。URL hash 应定位章节，不用多个章节共用一个高亮节点来伪装独立机制图。

## 实验实现

优先复用目标项目经过测试的核心。若静态页面不能运行完整服务，将可纯运行的解析、计算或转换抽到共享模块，或使用项目现有静态适配入口。测试有意义的不变量：状态保留、规则不变、输入拒绝、参数一致、取消不继续执行等。

让业务场景服务于原理，并控制数据规模：一座机架、四张 GPU、八个端口已经足够解释很多机制。按实际数据计算标签和汇总；不要把完整 Demo 的“48 端口”或固定设备名复制到小型教学 fixture。

代码面板可以展示输入、编译/转换产物、数据、状态/日志等实际对象。输出来自同一次执行，禁用仅随页签切换的静态伪指标。核心无法运行时，把演示标为“机制示意”并缩小结论；不要以静态界面宣称端到端工作正常。

完整 Demo 可以嵌入 iframe 并保留独立打开入口，避免初次加载抢占阅读。跨站可能禁止嵌入，验证后按目标环境选用独立链接。静态模拟输入、真实计算和后端集成分别说明清楚。
